# FuelGo Android App

The Android app is the FuelGo React frontend packaged as a native Android app with **Capacitor 8**. Every feature in the project brief is available in the app for all three roles (vehicle owner, provider, admin). It talks to the same Flask API and Socket.IO server as the web app.

| | |
|---|---|
| Package / app ID | `in.fuelgo.app` |
| Min / target SDK | Android 7.0 (API 24) / Android 16 (API 36) |
| Native project | `frontend/android/` (Gradle 8.14, AGP 8.13, JDK 21) |
| Built APK | `android-release/FuelGo-debug.apk` |

## What the native shell adds

| Capability | Implementation |
|---|---|
| Native GPS with the Android permission prompt | `@capacitor/geolocation` via `src/platform/index.js` (`getPosition`, `watchPosition`). Falls back to the browser API on the web. |
| Provider live location while driving | `watchPosition` → Socket.IO `provider:location` (REST fallback) |
| System notifications when the app is in the background | Socket.IO `notification` → `@capacitor/local-notifications` (Android 13+ permission requested after login) |
| Hardware back button | Closes an open dialog, then navigates back, then exits from the root screen (`@capacitor/app`) |
| Status bar, splash screen, adaptive launcher icon | `@capacitor/status-bar`, `@capacitor/splash-screen`, generated by `@capacitor/assets` from `frontend/assets/` |
| Haptic feedback on new notifications | `@capacitor/haptics` |
| Share receipt via the Android share sheet | `@capacitor/share` (replaces "Print" in the app) |
| Camera / gallery for problem photos and provider documents | WebView file chooser + `CAMERA` permission |
| Calls and navigation | `tel:` links open the dialer; "Navigate" opens Google Maps |
| Server address set at runtime | First-launch **Connect to FuelGo** screen; change it later from the login page |

Permissions declared in `AndroidManifest.xml`: `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `CAMERA`, `POST_NOTIFICATIONS`, `VIBRATE`. Cleartext HTTP is enabled so the app can reach a development server on your Wi-Fi. Serve the API over HTTPS in production.

## Running it on your phone

1. **Start the backend on your network**, not just localhost:
   ```powershell
   cd backend
   .\.venv\Scripts\Activate.ps1
   flask run --host 0.0.0.0        # or set FLASK_RUN_HOST=0.0.0.0 in backend/.env
   ```
   Allow Python through Windows Firewall (Private networks) when asked. Find your PC's IP with `ipconfig` (IPv4 Address, e.g. `192.168.1.5`).
2. **Install the APK.** Copy `android-release/FuelGo-debug.apk` to the phone (USB, Drive, WhatsApp to yourself…), open it, and allow *Install unknown apps* for the app you opened it from. With USB debugging on, you can instead run `adb install -r android-release\FuelGo-debug.apk`.
3. **Open FuelGo.** On the *Connect to FuelGo* screen, enter `http://<your-PC-IP>:5000` and tap **Connect**. The app checks `/api/v1/health` and remembers the address.
4. Sign in with a demo account (see the README) or create one. Allow location when asked.

The phone and the PC must be on the same Wi-Fi. If **Connect** fails, check the IP, that Flask shows `Running on http://0.0.0.0:5000`, and the firewall.

Two-device demo: run the vehicle owner on the phone and the provider in a desktop browser at `http://localhost:5173`, or the other way round. Live tracking, notifications and status updates flow between them in real time.

## Building the APK

Requirements: Node 20+, **JDK 21** and the **Android SDK** (platform 36, build-tools 35). Android Studio provides both, or use the command-line tools as below.

```powershell
cd frontend
npm install
npm run android:build        # web build → cap sync → gradlew assembleDebug
# → android-release\FuelGo-debug.apk
```

`scripts/build-android.mjs` uses `JAVA_HOME` / `ANDROID_HOME` if set, and otherwise looks in `%USERPROFILE%\android-tools\jdk-21*` and `%USERPROFILE%\android-tools\sdk`.

Command-line toolchain setup (what was used on the build machine):

```powershell
# JDK 21 (Eclipse Temurin) and Android command-line tools, unzipped under %USERPROFILE%\android-tools
#   https://adoptium.net/temurin/releases/?version=21
#   https://developer.android.com/studio#command-line-tools-only  → sdk\cmdline-tools\latest\
$env:JAVA_HOME = "$env:USERPROFILE\android-tools\jdk-21.0.13+9"
$sdk = "$env:USERPROFILE\android-tools\sdk"
& "$sdk\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root=$sdk --licenses
& "$sdk\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root=$sdk "platform-tools" "platforms;android-36" "build-tools;35.0.0"
```

Other scripts:

| Command | Does |
|---|---|
| `npm run android:sync` | Rebuild the web app and copy it into `android/` (after any frontend change) |
| `npm run android:open` | Open the native project in Android Studio (to run on an emulator or debug) |
| `npm run android:release` | Unsigned release APK. Sign it with your keystore (`apksigner`) before distributing. |
| `npm run android:assets` | Regenerate launcher icons and splash screens from `scripts/make-app-assets.mjs` |

Optional: set `VITE_API_URL` in `frontend/.env.android` to pre-fill a default server (e.g. a deployed HTTPS API), so users skip the connect screen.

## Limitations

- **Background GPS:** provider location is shared while the app is open. Android pauses WebView JavaScript when the app is fully backgrounded, so long background tracking would need a foreground-service plugin.
- **Notifications** come over the live Socket.IO connection, so they arrive while the app is running (foreground or recently backgrounded). Push notifications when the app is closed would need Firebase Cloud Messaging and a Firebase project.
- **Debug build:** the APK is debug-signed, which is fine for installing on your own devices and for a demo. Publishing to the Play Store needs a release keystore and an HTTPS backend.
- **OpenStreetMap tiles** are loaded from the public tile servers (fine for a demo). Heavy use needs a tile provider with an API key.
